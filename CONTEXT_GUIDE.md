# Проверка увеличенного контекста

Дополнение к `EXPERIMENT_GUIDE.md`: сравнение пространственной модели, Transformer и гибрида на 128, 256 и 512 байтах контекста. Итоговые значения находятся в `CONTEXT_RESULTS.md` и `CONTEXT_RESULTS.json`.

## Условия

Корпус и его разделение оставлены прежними. Для 256 и 512 байт выполнены новые обучения с нуля, по три seed (42, 43, 44) каждой модели. Для 128 байт переоценены прежние веса из `runs/natural_v1`, без нового обучения.

Во всех длинах шаг предсказывает 1024 байта: batch 8 при контексте 128, 4 при 256 и 2 при 512. Поэтому после 500 обновлений каждая модель видит 512000 целевых байт. Есть и отдельное состояние после 45 секунд накопленного времени обучения. Само внимание и остальная модель вычисляются в FP32; настройки оптимизатора сохранены.

Для оценки используется один и тот же префикс validation/test с 70144 целевыми байтами. Его длина кратна всем трём контекстам. Это позволяет сравнивать ошибки на одних и тех же позициях. Полный train-корпус не обрезается. Из-за общего префикса результат 128 немного отличается от исходного `NATURAL_RESULTS.md`.

Внутри каждой длины почти выровнено число параметров. Между длинами растёт таблица позиционных embedding. При изменении batch число независимых последовательностей за шаг тоже меняется; это ограничивает выводы о чистой пользе далёкой истории. Байты не равны обычным subword-токенам больших LLM.

## Что добавлено в код

- `spatiallm.experiment --eval-targets N` — общий префикс оценки. `N` должен быть положительным, кратным `--seq-len` и помещаться в обе части. Без этого аргумента прежнее поведение сохраняется.
- `spatiallm.context_eval` — переоценка существующих checkpoint на общем префиксе с проверкой SHA-256 исходных данных; исходные файлы и веса остаются без изменений.
- `tools/compare_contexts.py` — проверка сопоставимости трёх завершённых опытов и построение общей сводки. Скрипт проверяет хеши корпуса и оценочного префикса, seed, бюджеты байт/шагов, точность вычислений и число оценённых целей.
- Два теста модели и данных: сохранность train при ограничении оценки и причинность/обратное распространение всех трёх архитектур при контексте 512. Ещё три теста проверяют парную сводку и отклонение несопоставимых бюджетов/оценочных позиций. Всего в комплекте 21 тест.

## Повторение

Окружение `.venv` и данные уже находятся в проекте. Команды выполняются из его корня, последовательно:

```powershell
Set-Location 'path\to\SpatialLM-Mini'
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m spatiallm.context_eval --source runs/natural_v1 --out runs/context128_repeat --targets 70144 --device cuda
.\.venv\Scripts\python.exe -m spatiallm.experiment --seq-len 256 --batch-size 4 --eval-targets 70144 --steps 500 --seconds 45 --seeds 42 43 44 --out runs/context256_repeat --device cuda
.\.venv\Scripts\python.exe -m spatiallm.experiment --seq-len 512 --batch-size 2 --eval-targets 70144 --steps 500 --seconds 45 --seeds 42 43 44 --out runs/context512_repeat --device cuda
```

Имеющиеся каталоги не перезаписываются. Результаты по времени могут получить другое число шагов из-за текущей нагрузки компьютера. `context_eval` проверяет соответствие данных исходному опыту и применяет один и тот же префикс ко всем его snapshot-файлам.

Если прежних checkpoint для 128 нет, можно обучить новую базовую серию: `.\.venv\Scripts\python.exe -m spatiallm.experiment --seq-len 128 --batch-size 8 --eval-targets 70144 --steps 500 --seconds 45 --seeds 42 43 44 --out runs/context128_fresh --device cuda`. Это новый запуск с собственными измерениями времени. Компактный архив кода и результатов не содержит веса; все веса сохранены в локальном проекте.

Основная сводка для сохранённых стандартных имён каталогов строится командой:

```powershell
.\.venv\Scripts\python.exe tools/compare_contexts.py --root runs --out CONTEXT_RESULTS.md --json-out CONTEXT_RESULTS.json
```

Для повторной сводки положите три повторных опыта в отдельный каталог под именами `context128_common`, `context256_v1`, `context512_v1`, затем передайте его через `--root`. Исходные имена выбраны для конкретного протокола этого опыта; скрипт проверяет 3 seed, 500 шагов и 45 секунд.

Пример генерации на модели с контекстом 512:

```powershell
.\.venv\Scripts\python.exe -m spatiallm.generate --checkpoint runs/context512_v1/hybrid_seed42/equal_time.pt --device cuda --prompt 'Elizabeth ' --max-new-tokens 200
```

Экспериментальные checkpoint содержат веса и метрики для генерации/оценки. Для продолжения обучения через `spatiallm.train` по-прежнему нужны его собственные полные checkpoint с optimizer/RNG.

## Где сохранены результаты

- `runs/context128_common/results.json` — новые оценки прежних весов на общем префиксе; прежние оценки также сохранены внутри записей.
- `runs/context256_v1/` и `runs/context512_v1/` — новые веса двух состояний для каждой модели и seed, метрики, протоколы и логи.
- `CONTEXT_RESULTS.md`, `CONTEXT_RESULTS.json` — общая сводка.
- `backups/context_v1_20261109/` — прежние версии файлов перед обновлением.

Отчёт и сводка не являются тестом статистической значимости. Один роман и три seed позволяют увидеть устойчивость результата в этом масштабе; для обобщения нужны другие данные, более длинное обучение и отдельные задачи на дальние зависимости.
