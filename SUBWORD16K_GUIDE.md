# Проверка на 16 384 токенах GPT-2

Это отдельное дополнение к байтовым опытам SpatialLM-Mini. Здесь используется стандартный GPT-2 BPE-токенизатор с 50257 токенами словаря. Один токен может содержать часть слова, слово, пробелы или байты символа. Предобученные веса GPT-2 не загружаются: все три модели обучаются с нуля.

## Данные

Использованы те же неизменённые UTF-8 файлы `data/natural/train.txt`, `validation.txt`, `test.txt` из романа *Pride and Prejudice* Джейн Остин. Их исходные SHA-256 сохранены и проверяются вместе с SHA-256 последовательностей токенов. Токенизатор фиксированный, его не подбирали по этому корпусу.

Получилось 141979 обучающих токенов, 18537 validation и 18225 test. Части кодируются независимо; окна не пересекают границы train/validation/test. В train среднее соотношение — около 3.96 байта исходного UTF-8 на токен. Поэтому 16384 токена здесь представляют существенно больший текст, чем прежние 16384 байта.

Для каждой оценки используются первые 16385 токенов соответствующей части: 16384 входных токена предсказывают 16384 следующих. Эти позиции одинаковы у всех моделей и seed. Оставшиеся 2152 возможных validation-цели и 1840 test-целей исключены одинаково. Одна длинная последовательность на часть — ограничение этого небольшого корпуса.

Данные: `data/subword16k/tokens.pt`, описание и хеши: `data/subword16k/manifest.json`. Локальный кэш словаря GPT-2: `data/gpt2_cache/`. При наличии этих файлов повторная загрузка словаря из интернета не нужна.

## Экономия памяти

Применены одинаковые меры ко всем трём архитектурам:

- FP16 autocast для вычислений, FP32 параметры и AdamW, GradScaler с начальным масштабом 128.
- Activation checkpointing всех блоков: часть промежуточных данных пересчитывается при backward вместо хранения.
- Выходной слой рассчитывается порциями по 512 позиций. Для каждой позиции используется **весь словарь из 50257 токенов**. Нормализация softmax и усреднение loss не сокращаются; повторный расчёт порций при backward ограничивает память.
- Обычные Transformer-слои используют PyTorch `EFFICIENT_ATTENTION`. Переход на квадратичный по памяти math-алгоритм запрещён. В пространственных слоях остаётся прежний разреженный геометрический граф.

Режим Efficient Attention исправлять не требуется: он вычисляет полное причинное внимание, экономя промежуточную память. В данной Windows-сборке PyTorch FlashAttention не скомпилирован. Доступный Efficient Attention успешно прошёл реальные прямой и обратный проходы при контексте 16384. [Документация PyTorch](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention.html).

`LanguageModel.forward_loss()` проверен сравнением потерь и всех градиентов с обычным расчётом, включая dropout, неполную последнюю порцию и пересчёт блоков. Старая байтовая генерация и `train.py` отклоняют subword-конфиги, чтобы случайно не интерпретировать GPT-2 ID как байты. Прежние байтовые checkpoint остаются совместимыми.

## Протокол

Три архитектуры, seed 42/43/44, hidden 128, 4 слоя, 4 головы, batch 1, контекст 16384. Гибрид чередует spatial и Transformer. FFN имеют ширины 628/512/570 для почти равного числа параметров: около 9.32 млн у каждого варианта. Learning rate 0.0006, AdamW weight decay 0.01, clipping 1.0, dropout 0. Включены deterministic algorithms, TF32 выключен.

Сохраняются два состояния каждого запуска:

1. После одинаковых **100 обновлений** — 1638400 обучающих токенов.
2. После первого завершённого шага за **180 секунд накопленного времени обучения**. В бюджет входят выбор батча, передача на GPU, forward, backward, пересчёт данных, clipping и optimizer. Прогрев, валидация, сохранение и генерация исключены.

Для каждого seed все модели получают одинаковые обучающие окна в одинаковом порядке. Порядок архитектур меняется между seed. Пилот использовался для проверки памяти и выбора временного бюджета; после этого параметры основного опыта фиксируются. Test не применяется для настройки, остановки или выбора лучшего checkpoint.

## Запуск

Из корня проекта, с существующим CUDA-окружением:

```powershell
Set-Location 'path\to\SpatialLM-Mini'
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m pip install -r requirements-subword.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
# Короткая проверка трёх моделей, по три шага:
.\.venv\Scripts\python.exe -m spatiallm.subword16k pilot --steps 3 --seeds 42 --out runs/subword16k_pilot_repeat
# Полный предварительный опыт, последовательно на одной GPU:
.\.venv\Scripts\python.exe -m spatiallm.subword16k run --steps 100 --seconds 180 --seeds 42 43 44 --out runs/subword16k_repeat
```

Используйте новый `--out`: существующие опыты не перезаписываются. Размер словаря и модель фиксированы этим протоколом. Доступны `--chunk-size`, `--lr`, `--seq-len`; изменение этих аргументов создаёт отдельный опыт с другими условиями. При изменении контекста все три части данных должны содержать минимум `seq_len+1` токенов.

Для подготовки токенов заново, без перезаписи имеющихся:

```powershell
.\.venv\Scripts\python.exe -m spatiallm.subword16k prepare --text data/natural --data data/subword16k_rebuilt
```

Генерация:

```powershell
.\.venv\Scripts\python.exe -m spatiallm.subword16k generate --checkpoint runs/subword16k_v1/hybrid_seed42/equal_time.pt --prompt 'Elizabeth ' --count 64
```

Для генерации вычисляются только logits последней позиции; большая матрица `context × vocabulary` не создаётся. Длинный prompt обрезается по токенам. KV-cache пока нет: контекст пересчитывается на каждом шаге.

## Файлы

- `spatiallm/subword_data.py` — GPT-2 токенизация, подготовка и проверка токенов.
- `spatiallm/subword16k.py` — пробный запуск, основное сравнение и генерация.
- `spatiallm/model.py` — общий backbone, пересчёт блоков и вычисление loss порциями.
- `tests/test_subword.py` — эквивалентность loss/градиентов, dropout, неполные порции, токенизация и совместимость.
- `runs/subword16k_v1/` — девять запусков, 18 состояний, протокол и полные метрики.
- `requirements-lock-subword-cuda.txt` — точные версии проверенного окружения.

Веса опыта — snapshots для оценки и генерации. Они не содержат optimizer/RNG для продолжения обучения. Обычный байтовый `spatiallm.train` по-прежнему сохраняет полный checkpoint для resume. За одинаковое время повторный запуск может выполнить немного другое число шагов; одинаковое число шагов и данные дают более строгую проверку воспроизводимости в одном окружении.

## Границы выводов

Это маленькие модели, один английский роман и короткое обучение. Большая длина окна не доказывает извлечение информации с дальних позиций — для этого нужен отдельный контрольный тест. Token perplexity здесь относится к GPT-2 токенам; её нельзя напрямую сравнивать с byte perplexity прежних опытов.

Одновременно с длиной изменились токенизатор, словарь, число параметров, точность и методы расчёта памяти. Поэтому этот опыт не изолирует единственный эффект увеличения контекста. Внутри текущего опыта условия трёх архитектур сопоставимы; выводы относятся к этим реализациям на RTX 3050. Для оценки роли именно геометрии нужен тот же граф без обучаемых 3D-координат. Для общих выводов также нужны другие корпуса и более длинное обучение.
